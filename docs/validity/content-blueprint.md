# Prospective-bank content blueprint

## Status and evidence boundary

This document defines the structural campaign contract for experimental PCDA
source-bank admission while Coffee Chat Bench remains `not_active`. It does not
author the source bank, record a model call, establish benchmark validity,
report a measured result, or activate the repository.

Admission records contain supplied, reviewable evidence. Local evaluation
checks structure, completeness, deterministic fixture outcomes, provenance
roles, and campaign balance. It does not infer that a model performed the
author, critic, or adversary work and does not replace future campaign
receipts.

## Campaign shape

The prospective campaign contains exactly 144 public synthetic draft records.
Exactly 96 families may enter the fixed bank:

| Partition   | Admitted families |
| ----------- | ----------------: |
| Development |                24 |
| Calibration |                24 |
| Release     |                40 |
| Bridge      |                 8 |

The admitted bank has exactly three domains, four operations, and two
difficulties, with four unique cases in every domain-operation-difficulty
stratum. This is `3 x 4 x 2 x 4 = 96`; it is not a weighted score.

The campaign uses exactly eight perspective pairs. Every admitted pair appears
in every admitted domain. Both A and B are synthetic public inputs, express a
real contrast, and remain viable within their declared context; the pair must
not encode one side as universally superior. The irrelevant perspective has
separate pair provenance.

The canonical catalog is `perspectives/catalog.json`. It contains exactly
`speed/assurance`, `exploration/convergence`, `local/systems`,
`novelty/precedent`, `agency/guidance`, `breadth/depth`,
`reversible/committed`, and `explicit-process/adaptive-judgment`. Its rights
declaration identifies the text as synthetic public MIT material and states
that neither side is globally superior.

## Semantic author sources

Authors provide `bank/blueprints/product.json`, `research.json`, and
`operations.json`. Each file contains exactly 48 semantic drafts: 32 with
`admitted` intent and 16 with `rejected` intent. Intent is campaign-planning
metadata only. Supplied checks and provenance determine admission, and the
fixed campaign audit remains authoritative if outcomes differ from intent.

`bank/blueprints/**` is the authored sealed admission source. It is visible to
benchmark maintainers for admission audit, but is never candidate-visible
runtime input and is not copied into a candidate projection. Its semantic
contents are the only materializer inputs; people do not edit derived campaign
records to change an admission outcome.

Semantic drafts contain task, an evidence object map keyed by evidence ref,
pair selection, decisions, non-goal, provenance, and explicit check evidence.
Map values are non-empty content strings; refs use the safe key contract and
cannot be duplicated structurally. They do not contain evidence digests,
perspective digests, case source digests, admission outcomes, campaign digests,
or selected-bank digests. The runtime parser and
`schemas/domain-blueprint.schema.json` reject those author-controlled fields.

## Deterministic materialization

Run:

```sh
node --experimental-strip-types src/cli.ts materialize-bank \
  --catalog perspectives/catalog.json \
  --blueprints bank/blueprints \
  --destination bank
```

The materializer computes content and source digests, calls `evaluateDraft`,
retains all 144 records in `prospective/admission-ledger.jsonl`, then calls
`auditProspectiveBank` and `selectReleaseBank`. A valid campaign writes the 96
selected cases under `development/`, `calibration/`, `release/`, and `bridge/`
plus `campaign.json`. The campaign records source-blueprint, prospective, and
selected-bank digests, exact counts, and audit state.

All generated bytes are staged and round-tripped through the existing case,
bank, admission-record, and campaign validators before publication. Evidence
map entries are sorted by ref before the materializer creates the Task 4A
CaseBundle evidence array and derives each content and case-source digest.
Draft and blueprint traversal order does not change output bytes. Publication
replaces only a destination carrying the exact generated marker; an invalid
campaign does not create or modify a destination, and an unmanaged destination
is never replaced. Every existing destination path component is inspected
without following it; a symlinked ancestor or destination is rejected before
staging.

`bank/campaign/**` is the generated publication source. It carries the public
prospective ledger and selected public case bank, including its marker and
campaign digests. A candidate receives only a condition-specific projection
derived from one selected case. Blueprints and the generated sealed judgment
are never candidate-visible; the projection's separate verifier consumes the
judgment only after candidate execution.

## Draft content contract

Every prospective record retains its complete Task 4A case bundle, including a
candidate-visible instruction and deliverable, content-bearing evidence,
public A/B/irrelevant perspectives, decision prompts and exhaustive region
options, hidden accepted-region mappings, evidence obligations, and one
explicit non-goal. Runtime case parsing remains authoritative for semantic
digests, references, sensitive/invariant partitions, and accepted-region
subsets.

An admitted family must contain at least one sensitive and one invariant
decision. Authors should declare multiple acceptable regions whenever more
than one response region is genuinely equivalent; multiplicity must not be
invented to satisfy a count. The counterfactual and locality evidence explains
which sensitive regions move and which obligations remain fixed.

## Provenance roles

Each draft records one author, critic, and adversary role. The three role IDs
are a distinct permutation of:

- `gpt-5.6-sol`
- `gpt-5.6-terra`
- `gpt-5.6-luna`

The decisive admission model is the critic or adversary and is never the
author. These fields are structural provenance declarations, not evidence of a
live call by themselves.

## Conjunctive admission checks

Every named check has an explicit `passed` boolean and non-empty `reason`.
Missing or failed checks reject the draft; no score, weight, majority, or
compensation is permitted.

| Check                          | Required structural evidence                                                                       |
| ------------------------------ | -------------------------------------------------------------------------------------------------- |
| `taskOnlyUnderdetermination`   | Task and evidence without a perspective do not uniquely determine the sensitive choice.            |
| `perspectiveOnlyInsufficiency` | A perspective without task evidence cannot establish a valid manifest.                             |
| `counterfactualShift`          | A and B move at least one declared sensitive accepted region.                                      |
| `locality`                     | The shift is limited to the intended sensitive decisions and preserves unrelated obligations.      |
| `irrelevantStability`          | The irrelevant perspective preserves the declared accepted regions.                                |
| `paraphraseInvariance`         | Meaning-preserving task/perspective paraphrases preserve accepted regions.                         |
| `antiEcho`                     | Visible inputs do not reproduce an accepted manifest or leak the hidden oracle.                    |
| `rights`                       | Draft, evidence, and perspectives are synthetic public material within the repository's MIT scope. |
| `deterministicOraclePass`      | The deterministic Oracle fixture is accepted by the projected verifier.                            |
| `deterministicNoOpFailure`     | The deterministic no-op fixture is rejected.                                                       |
| `deterministicListAllFailure`  | The deterministic list-all fixture is rejected.                                                    |

## Audit and selection

`auditProspectiveBank` retains all 144 records, including rejected drafts, and
reports explicit checks and reasons for campaign size, record consistency,
identity uniqueness across every admitted and rejected record, admitted count,
partition split, factorial balance, and eight-pair cross-domain coverage.
Malformed records fail closed with indexed reasons and never disappear into an
uncaught parser error.

`selectReleaseBank` requires exactly 96 records whose supplied admission
evidence already passed; 95 or 97 passing records invalidate the campaign.
Selection is stable by draft identity and source digest. It returns those 96
records only when all split, balance, uniqueness, and pair coverage constraints
are satisfied together. Otherwise it returns an explicit invalid report and an
empty selection; it does not drop a passed record, fill gaps, invent evidence,
promote rejected drafts, or emit a partial best-effort bank.

Generated files remain public synthetic source material. Their structural
provenance declarations and deterministic fixture evidence do not establish
that a live model call occurred, that the repository is active, or that any
candidate was measured.
